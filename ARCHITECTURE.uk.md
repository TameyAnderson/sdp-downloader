# s.d.p downloader — схема роботи

<p><a href="ARCHITECTURE.md">English</a> · <b>Українська</b></p>

Повний опис того, як бот обробляє посилання: від повідомлення до готового файлу.

---

## 1. Точки входу

| Звідки | Що приймає |
|---|---|
| **Приватний чат** | посилання, `mp3`-слово, таймкоди `0:10-0:30`, файл cookies, команди |
| **Груповий чат** | посилання (реагує лише на них, без спаму) |
| **Mini App** | посилання + вибір якості/бітрейту, керування налаштуваннями |

У режимі **LITE** лишається тільки середній рядок: бот працює виключно в групах, у приваті відповідає короткою довідкою.

---

## 2. Шар доступу (перед будь-якою роботою)

1. **Білий список чатів** — один тумблер:
   - **вимкнено** (за замовчуванням): бот працює в будь-якому чаті, усім доступне все;
   - **увімкнено**: працює лише в чатах зі списку, у приваті відповідає тільки адміну.
2. **Рівнів доступу немає** — кому дозволено, тому дозволено все: YouTube, плейлисти, MP3, All-in.
   Окремо стоїть лише `admin` — йому Mini App (панель) і службові команди.
3. **Ліміти**: максимум силок з одного повідомлення, максимум паралельних завантажень
   на юзера й загалом.
4. **LITE**: доступ вирішує змінна `ALLOWED_CHATS` — порожня означає будь-яку групу.

---

## 3. Розбір посилання

```
текст повідомлення
   ↓ regex, зібраний ЛИШЕ з увімкнених сервісів
знайдені URL
   ↓ визначення платформи (реєстр із 19 сервісів; All-in — останній)
   ↓ розгортання плейлистів (до ліміту)
   ↓ чистка трек-параметрів (Instagram ?igsh=…)
   ↓ таймкоди для обрізки + якість/бітрейт з Mini App
черга завдань
```

---

## 4. Рушії та ланцюжки фолбеків

Три рушії з різними ролями — жоден не дублює інший:

| Рушій | Унікальна роль |
|---|---|
| **tikwm** | TikTok фото та каруселі |
| **yt-dlp** | відео, YouTube, сходинки якості, MP3 з тегами |
| **Cobalt** | Instagram/Facebook **без cookies**, страховка при поломці екстрактора |

**Ланцюжки за платформою:**

```
TikTok /photo/  :  tikwm → Cobalt → yt-dlp
TikTok відео    :  yt-dlp → Cobalt
Instagram / FB  :  [є cookies?] yt-dlp → Cobalt
                   [немає]      Cobalt → yt-dlp
YouTube         :  yt-dlp (+PO-token, Deno) → Cobalt
Spotify/Deezer  :  публічний oEmbed (лише назва треку) → пошук на YouTube → аудіо
All-in (інші)   :  yt-dlp
```

**Дві хвилі:**
1. **Сувора** — усі рушії мусять дати ціле відео **зі звуком**; німе або «фото замість відео» відхиляється.
2. **М'яка** — запускається, тільки якщо щось відхилили за якістю; тут приймається німий файл як останній варіант.
   Якщо всі рушії впали намертво — друга хвиля пропускається (не витрачає час).

## 5. Перевірка перед відправкою

Файл не піде користувачу, поки не пройде всі перевірки:

```
завантажений файл
   ├─ обрізане завантаження?      (реальний розмір vs Content-Length)
   ├─ є відеопотік?               (ffprobe)
   ├─ тривалість > 0.5 с?         (відсікає «нульові» биті файли)
   ├─ повний декод без помилок?   (ffmpeg, для Cobalt-файлів)
   ├─ достатньо кадрів?           (якщо тривалість невідома)
   └─ є звук?                     (німе → інший рушій)
        ↓
   не пройшов → наступний рушій у ланцюжку
```

---

## 6. Відправка

- **Метадані обов'язково**: ширина, висота, тривалість, мініатюра, `supports_streaming` — без них Telegram показує відео «битим».
- **Flood control**: 429 → чекає `retry_after` і повторює; пауза між відправками в один чат.
- **Розмір**: до **2 ГБ** через локальний Bot API, або 50 МБ через хмарний.
- Кеш `file_id` — повторне посилання надсилається миттєво (вимикається).

---

## 7. Стан і фонові процеси

**Зберігається:**
- SQLite: події (статистика), налаштування, білі списки. Увімкнений WAL, тож
  панель читає, поки пишеться подія; версія схеми лежить у `PRAGMA user_version`
  і піднімається нумерованими міграціями. Одне з'єднання на робочий потік,
  з перевикористанням.
- cookies — на volume, права 600. Записуються двічі: файл у форматі Netscape для
  `yt-dlp` і власний `cookies.json` для Cobalt, щоб запасний рушій мав ту саму сесію.
- кеш `file_id`. У ключі є якість, бо 480p і 1080p одного посилання — різні
  файли. Кеш позначений тим Telegram API, від якого отримані ідентифікатори, і
  скидається при його зміні: `file_id` дійсний лише на сервері, що його видав.
  Запис відкладається за межі циклу подій.

**Раз на N годин перевіряє** (інтервал редагується в панелі, за замовчуванням 2):
- нові версії yt-dlp / aiogram / Cobalt;
- новий коміт у репозиторії, за яким стежить (апстрім або свій форк) — порівнює
  з **робочим** комітом, тому не просить redeploy даремно;
- строк дії cookies — попереджає за N днів.

**На кожну джобу:** якість, обрізка, назва й причина невдачі живуть у
contextvars, і кожна точка входу створює власну задачу — саме на цьому
тримається ізоляція. У джоби є дедлайн (для коротких відео й довгого YouTube
різний), тож повільне падіння не тримає слот, а рушій, який кілька разів
поспіль упав на одній платформі, ставиться на паузу. Двоє з однаковим
посиланням дають одне завантаження.

**На старті й при зупинці:** самоперевірка повідомляє про ffmpeg, Cobalt,
провайдер PO-токенів, справжній ліміт файлу й режим приватності в групах;
залишки робочих тек від попереднього запуску прибираються. `SIGTERM` зупиняє
полінг, дає активним джобам дійти в межах дедлайну й скидає кеш на диск.

У **LITE** нічого зі списку «Зберігається» немає: ні бази, ні кешу, ні cookies
з можливістю запису. Тимчасові файли живуть у `/tmp` в оперативній пам'яті.

## 8. Контейнери

| Сервіс | Роль |
|---|---|
| **video-bot** | сам бот + Mini App API |
| **cobalt-api** | рушій Cobalt (локальний, приватний) |
| **bgutil-provider** | PO-токени для обходу захисту YouTube |
| **telegram-bot-api** | локальний Bot API → ліміт 2 ГБ *(профіль bigfiles)* |
| **cloudflared** | HTTPS-тунель для Mini App *(профіль miniapp)* |
| **autoheal** | перезапуск, якщо бот перестав відповідати на `/health` |

У **LITE** їх два: `video-bot` і `cobalt-api`. Провайдер PO-токенів вмикається
профілем `youtube`, якщо YouTube почне вимагати підтвердження.

## 9. Загальний потік одним поглядом

```
Користувач ──► Telegram ──► s.d.p bot
                              │
                     доступ + ліміти
                              │
                     розбір посилання
                              │
         ┌────────────────────┼────────────────────┐
      tikwm               yt-dlp                Cobalt
         └────────────────────┼────────────────────┘
                     перевірка цілісності
                              │
                   метадані + flood control
                              │
Користувач ◄── відео / фото / MP3 ◄── Telegram
```

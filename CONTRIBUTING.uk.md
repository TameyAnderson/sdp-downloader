# Внесок у проєкт

<p><a href="CONTRIBUTING.md">English</a> · <b>Українська</b></p>

Радий будь-якій допомозі: від виправленої одруківки до нового рушія.

## З чого почати

```bash
git clone https://github.com/TameyAnderson/sdp-downloader.git
cd sdp-downloader
cp .env.example .env          # встав свій BOT_TOKEN
docker compose up -d --build
```

Тести — без жодних залежностей, окрім `pyyaml`:

```bash
cd tests && python -m unittest discover -s . -p "test_*.py" -v
```

Прогони їх **перед** тим, як надсилати PR. Те саме зробить CI, але швидше
дізнатись самому.

## Правила, які економлять час

- **Один PR — одна зміна.** Великі змішані правки складно перевіряти.
- **Нова можливість — новий тест.** Хоча б один, який падає без твоєї зміни.
- **Двомовність обов'язкова.** Кожен новий напис додається і в `uk`, і в `en`
  (у `T` в `bot.py` та у словниках `I` в `index.html`). Тест це перевіряє.
- **Ніяких секретів.** cookies, токени, id чатів — навіть у прикладах.
  Тест шукає їх у всьому репозиторії.
- **Нова змінна оточення** має з'явитись у `.env.example` і в потрібному compose,
  інакше тест деплою впаде.

## Що варто обговорити до реалізації

Відкрий issue, перш ніж братись за:

- нові рушії та зовнішні сервіси;
- зміни моделі доступу;
- усе, що починає писати нові дані на диск;
- рефакторинг структури файлів.

Не тому що «не можна», а щоб не витрачати вечір на те, що не підійде за задумом.

## Про що ми точно не домовимось

- обхід DRM (Spotify, Deezer, будь-які захищені сервіси);
- емуляція активності акаунтів та обхід антибот-захисту;
- усе, що допомагає обійти закон замість того, щоб просто зберегти собі відео.

Такі PR закриваються без обговорення.
